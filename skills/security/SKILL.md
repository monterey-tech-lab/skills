# SaaS Security

Production guardrails for agents building or reviewing scalable multi-tenant B2B/SaaS products (MVP through enterprise technical readiness). Primary examples use TypeScript/Node, PostgreSQL, and cloud patterns (AWS/GCP). Complements `swift` for Apple-platform secrets and distribution—do not duplicate Keychain or notarization here. Defensive guidance only: no exploit PoCs. Compliance content maps technical controls; it is not legal advice.

## Out of Scope

Offensive security / exploit writing; novel cryptography; GDPR/HIPAA/PCI legal opinions; Apple Keychain/notarization (`swift`); pure SIEM/SOC tooling unrelated to the product codebase; UI craft (`craft-and-taste`).

## Five Pillars

Map every change to Confidentiality, Integrity, Availability, Authentication, and Non-Repudiation (STRIDE’s property side). Treat **Authorization** as first-class beside them—Broken Access Control is OWASP Top 10:2025 A01.

## Operating Loop

Run on every security-relevant request. Stop when each step's criterion is met.

```text
Security progress:
- [ ] 1. Threats: name trust boundaries and top STRIDE abuses for the change
- [ ] 2. Authn: identity verified; MFA for privileged roles; revocation path exists
- [ ] 3. Authz + tenant: every object access authorized; tenant from trusted context; DB isolation
- [ ] 4. Data path: validation, no injection, safe errors, no secrets/PII in logs or client payloads
- [ ] 5. Abuse: rate limits, idempotency on side effects, verified webhooks, locked CORS
- [ ] 6. Ops: audit event if high-risk; backups/IR considered; no new public attack surface
```

**Completion criterion:** every checkbox satisfied in the answer or shipped change, and no CRITICAL rule from sections 1–4 violated.
